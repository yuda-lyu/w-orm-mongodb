new WOrmMongodb(optopt) → {Object}

Description:

  • 操作資料庫(MongoDB)

    本套件之主鍵欄位固定為id，尚未支援由呼叫端指定。id為無業務語義之識別碼。 opt.autoGenPk預設為true，insert、save與insertGfs於輸入未帶有效id時自動產生；del於任一設定下皆不補值。 opt.autoGenPk為false時套件一律不產生id，未帶有效id者以reject拋出，且id之唯一性與格式皆由呼叫端自負。

    字串良構檢核(w-orm系列一致，不隨opt.autoGenPk改變)：BSON會把孤立代理字元(String.prototype.isWellFormed()為false者)無聲改寫為U+FFFD， 使不同id寫成同一id、鍵名撞鍵、寫入值與讀回值不同，故於到達MongoDB之前檢核並拒收： 主鍵id不得為空字串或含孤立代理字元、NUL；寫入資料(insert、insertBulk、save)之字串值與鍵名(含巢狀物件與陣列元素)不得含孤立代理字元(值之NUL不檢查)； opt.url、opt.db、opt.cl含孤立代理字元者於建構時throw(訊息invalid opt.<名>: string contains lone surrogate)，建構時即取值，其後改動opt不影響本實例。 insert、insertBulk、insertGfs整批reject且不寫入任何一筆；save、del、delGfs該筆ok為0並附err，同批其他筆照常；selectByPk、selectByPkGfs回傳null。 錯誤訊息為固定詞彙、不回顯值，如invalid id: string contains lone surrogate at [data[1].id]、invalid data: string contains lone surrogate at [data[1].meta.tags[0]]。 詳見README之字串良構檢核。

(async, static) delAll(findopt) → {Promise}

Description:

  • 依條件刪除多筆數據(破壞性操作，須審慎使用，非必要不用；刪除單筆請用del)，需與del分開，避免未傳數據導致直接刪除全表

    使用須知：

    1. 不給條件即刪除全部數據：find未給、為undefined或為{}時，刪除資料表內全部數據，不另行確認。給了條件才是部分刪除。
    2. 傳了值卻不是條件物件(null、陣列含[]與[{...}]、字串、數值、布林、函數、Date、RegExp、Map、Set、類別實例等)， 一律整批reject，不視為{}，不刪除任何數據。
    3. 條件僅支援系列白名單：欄位等值{欄:純量}(多欄為AND)、欄位運算子$eq $ne $gt $gte $lt $lte(值為純量)與 $in $nin(值為純量陣列)、文件層$and $or(值為條件物件之非空陣列，最多1000項)。純量為字串、有限數字、布林、有效Date； null僅可用於欄位等值、$eq、$ne。白名單外之運算子($not $nor $regex $options $exists $where $expr $text等)、 欄位層$and/$or、點路徑、函數值、Symbol鍵、undefined值、空的$nin/$and/$or等一律整批reject， 訊息為invalid find: 原因 at [路徑]，且不連線、不刪除任何數據。
    4. 與select共用同一檢核與同一條件，select(find)命中之數據即本函數刪除之數據； 建議先以select(find)確認命中範圍再刪除。
    5. 條件值若來自可能為undefined、null或空陣列之變數，呼叫端須先自行判斷；undefined值會reject而非被忽略， 空的$nin會reject，$in:[]則為恆假(刪除0筆)。
    6. 語意差異(MongoDB式，依伺服器原生行為，見README)：$ne(比較值非null)與$nin會命中欄位為null或缺欄之數據，$ne:null則僅命中欄位存在且非null者。 需明確表達時可用可攜寫法：排除null為{$and:[{f:{$ne:null}},{f:{$ne:x}}]}，含null為{$or:[{f:null},{f:{$ne:x}}]}。

    註: n為實際刪除筆數，恆等於nDeleted；條件無命中時回傳0亦屬正常結果

(async, static) insert(data, optionopt) → {Promise}

Description:

  • 插入數據，僅於id不存在時寫入，已存在者跳過且不覆寫 由MongoDB於唯一索引上原子完成[檢查id未存在]與[寫入]，併發時同一id僅有一次成功 註: 預設回傳單一聚合物件，n為輸入筆數，nInserted為實際插入筆數，全數已存在而nInserted為0屬正常結果 註: option.returnList為true時改回與輸入等長且保序之逐筆陣列，供呼叫端得知[是哪幾筆]為新數據， 聚合計數僅能回答[有幾筆]，而去重類呼叫端須知何者為新方能對其執行下游動作 註: opt.autoGenPk為true(預設)時未帶有效id者自動產生，為false時未帶有效id即reject且同批皆不寫入 註: 主鍵id含孤立代理字元或NUL，或資料之字串值、鍵名(含巢狀)含孤立代理字元者，於連線與寫入之前整批reject且同批皆不寫入， 訊息為invalid id: 原因 at [data[k].id]或invalid data: 原因 at [data[k].路徑]，以索引最小之不合格筆為準，不回顯值，error事件於reject前發出一次

(async, static) insertBulk(data) → {Promise}

Description:

  • 批次插入數據，全批視為一個單位：全部插入成功，或一筆都不寫入 任一筆之id已存在(含同批含重複id)即以reject拋出整批性錯誤，且不寫入任何一筆 註: 本函數非insert之加速版，兩者衝突政策不同——insert跳過已存在者而整批ok為1， 本函數則整批reject；需要逐筆處置者改用insert 註: n為輸入筆數，nInserted於成功時恆等於n；不提供逐筆結果，故不出現ok為0與err 註: opt.autoGenPk為true(預設)時未帶有效id者自動產生，為false時未帶有效id即reject且同批皆不寫入 註: 主鍵id含孤立代理字元或NUL，或資料之字串值、鍵名(含巢狀)含孤立代理字元者，於連線與寫入之前整批reject且同批皆不寫入，訊息格式同insert 註: 全有全無之達成方式依部署而異——具replica set或分片叢集者以交易包覆， standalone無交易可用而以補償動作達成，其限制詳見_insertBulkByCompensate
