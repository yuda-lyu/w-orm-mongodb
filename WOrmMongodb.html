WOrmMongodb

new WOrmMongodb(optopt) → {Object}

Description:

  • 操作資料庫(MongoDB)

    本套件之主鍵欄位固定為id，尚未支援由呼叫端指定。id為無業務語義之識別碼。 opt.autoGenPk預設為true，insert、insertBulk、save與insertGfs於輸入未帶id(id為undefined、null或空字串)時自動產生；del於任一設定下皆不補值。 呼叫端給了id而不合格者(非字串，如數字、布林、物件、陣列、String包裝物件、Symbol、BigInt；或含NUL、孤立代理字元)一律拒絕而不補值、不替換(訊息invalid id: 原因 at [data[k].id])， 因主鍵為資料之身分，給了錯值而換成新id寫入，事後無從對應；此拒絕不隨opt.autoGenPk改變。 主鍵只認自有可列舉之資料屬性(R-PKOWN-01，w-orm系列一致)：列之id為繼承(原型鏈上，如Object.create({ id })、類別原型上之getter、frozen原型，不論繼承值之型別)或自有不可列舉者視為未帶： insert、insertBulk、save、insertGfs於opt.autoGenPk為true時補新主鍵(以Object.defineProperty定義為自有可列舉之資料屬性，遮蔽原型上之值)，為false時照既有之未帶處置(整批reject)； del、delGfs視為未給主鍵(該筆ok為0，invalid id: not a string at [data[k].id])，不得以原型上之值刪除庫內同值之列。判定先以既有路徑取值，值為未帶即短路，只有值為給了才查描述子(不呼叫存取器)。 selectByPk、selectByPkGfs收純量，不適用；非主鍵欄之繼承欄位之處置不變(BSON只存自有可列舉屬性，不在本規則範圍)。 opt.autoGenPk為false時套件一律不產生id，未帶id者以reject拋出，且id之唯一性與格式皆由呼叫端自負。

    字串良構檢核(w-orm系列一致，不隨opt.autoGenPk改變)：BSON會把孤立代理字元(String.prototype.isWellFormed()為false者)無聲改寫為U+FFFD， 使不同id寫成同一id、鍵名撞鍵、寫入值與讀回值不同，故於到達MongoDB之前檢核並拒收： 主鍵id不得為空字串或含孤立代理字元、NUL；寫入資料(insert、insertBulk、save)之字串值與鍵名(含巢狀物件與陣列元素)不得含孤立代理字元(值之NUL不檢查)； opt.url、opt.db、opt.cl含孤立代理字元者於建構時throw(訊息invalid opt.<名>: string contains lone surrogate)，建構時即取值，其後改動opt不影響本實例。 insert、insertBulk、insertGfs整批reject且不寫入任何一筆；save、del、delGfs該筆ok為0並附err，同批其他筆照常；selectByPk、selectByPkGfs回傳null。 錯誤訊息為固定詞彙、不回顯值，如invalid id: string contains lone surrogate at [data[1].id]、invalid data: string contains lone surrogate at [data[1].meta.tags[0]]。 詳見README之字串良構檢核。

    讀取即拋錯之輸入(R-READABLE-01，w-orm系列一致)：呼叫端給的資料容器(data)、選項(option、opt)、主鍵(selectByPk、selectByPkGfs之pk)若讀取即拋錯(已撤銷之Proxy、Symbol.toStringTag或陷阱拋錯之物件、陣列length或[0]之讀取拋錯、拋錯之存取器)， 與[可讀而型別不符]分開處理(由wsemi之chkReadable辨識，且僅於判斷函數回false之分支內才探針，有效輸入不多讀)： insert、insertBulk、save、del、insertGfs、delGfs之data不可讀者整批reject(error事件於reject前恰發一次，不連線、不寫入、不刪除)，訊息為固定詞彙invalid data: must be a readable value， 不含原例外文字、不回顯值；insert之option與option.returnList、save之option與option.autoInsert不可讀者亦同(invalid option: must be a readable value、invalid option.returnList: …、invalid option.autoInsert: …)； selectByPk、selectByPkGfs之pk不可讀者整批reject(invalid pk: must be a readable value，error事件於reject前恰發一次，不連線)； insertGfs之u8a不可讀者訊息為invalid data[k].u8a: must be a readable value；建構時opt、opt.autoGenPk、opt.url、opt.db、opt.cl不可讀者同步throw(invalid opt: …、invalid opt.<名>: must be a readable value)。 容器可讀而其成員為拋錯之存取器者(opt.url、opt.db、opt.cl、opt.autoGenPk、option.returnList、option.autoInsert、長度為1之陣列data而[0]為存取器)於讀取處之try內捕捉，同樣轉為上列固定詞彙，不含存取器所拋之原例外文字(該文字由呼叫端之物件決定，可能含機敏字串)； 容器本身不可讀者(option、opt為已撤銷之Proxy等)以容器名(invalid option: …、invalid opt: …)。 資料內部之巢狀不可讀值(如id、欄位、陣列其後之元素、u8a為已撤銷之Proxy或拋錯之存取器，於複製處拋錯者)與頂層不可讀走同一通道：整批reject固定詞彙invalid data: must be a readable value，error事件恰一次(數據參數null)，不補值、不連線、不寫入、不刪除； 複製處(insert、insertBulk、save、del為深拷貝；insertGfs為陣列元素之讀取與展開，展開會執行元素自有可列舉之存取器，其餘只讀id與u8a之值；delGfs為陣列元素與其id之讀取，只讀id，其餘欄位不讀取)不分辨拋錯之原因，可讀而無法複製者(原型為null之Date、過深之巢狀)亦同，原例外文字不轉出； insertGfs、delGfs之id為不可讀之值者(非自有存取器，如已撤銷之Proxy)亦同(不再為invalid id: not a string)。範圍只到複製處為止：複製之後讀取原型上之存取器、繼承之存取器等所拋者仍為外來錯誤(經outErr遮除憑證)，不在此列。 入口階段之不可讀拒絕之error事件，數據參數一律為null；其後之整批拒絕與逐筆失敗之數據參數不變。 可讀而型別不符者維持既有處理：data為5、字串、null、{}、[]等視為無數據之正常結果，selectByPk、selectByPkGfs之pk為5、String包裝物件等回傳null，option.returnList與opt.autoGenPk非布林值取預設，opt.url、opt.db、opt.cl非字串不檢核； opt為null等原始值仍原樣拋出原生TypeError。select、delAll、delAllGfs之find不可讀者依條件(find)白名單以invalid find整批reject。 詳見README之破壞性變更。

    診斷輸出(R-DIAG-01)：本套件唯一會自行輸出者，為change與error事件之訂閱函數拋錯時(該錯誤不影響操作結果，故僅吞下並輸出)。遮罩與輸出由wsemi之getDiag單一擁有， 預設只輸出固定標籤與不含個資之摘要(操作別、錯誤類別與機器代碼)，不輸出訂閱函數所拋錯誤之訊息、堆疊與其中的資料值、id等。 opt.logDetail為true時改輸出標籤與遮罩後之細節(訂閱函數所拋之錯誤)，opt.funLog為函數時改交給它(label, safe, detail)、不寫console； 細節中之連線字串與帳密(opt.url內之帳號、密碼、查詢參數中名稱含pass/pwd/secret/token/credential/user者之值等)一律以取代，規則見wsemi之getDiag、getDiagSecrets。 對外之錯誤值(各操作之reject、error事件之訊息、逐筆結果之err)：驅動、後端與使用端程式拋出之值，若含連線憑證(連線字串、密碼、帳密並列形式、查詢參數內之秘密值等)則以取代， 不含憑證者原樣(身分不變)，單獨之帳號不遮；本套件自身以固定詞彙組成之錯誤不經遮罩。 各操作之resolve內容與事件payload不受診斷輸出影響。詳見README之Diagnostic output。

(async, static) delAll(findopt) → {Promise}

Description:

  • 依條件刪除多筆數據(破壞性操作，須審慎使用，非必要不用；刪除單筆請用del)，需與del分開，避免未傳數據導致直接刪除全表

    使用須知：

    1. 不給條件即刪除全部數據：find未給、為undefined或為{}時，刪除資料表內全部數據，不另行確認。給了條件才是部分刪除。
    2. 傳了值卻不是條件物件(null、陣列含[]與[{...}]、字串、數值、布林、函數、Date、RegExp、Map、Set、類別實例等)， 一律整批reject，不視為{}，不刪除任何數據。
    3. 條件僅支援系列白名單：欄位等值{欄:純量}(多欄為AND)、欄位運算子$eq $ne $gt $gte $lt $lte(值為純量)與 $in $nin(值為純量陣列)、文件層$and $or(值為條件物件之非空陣列，最多1000項)。純量為字串、有限數字、布林、有效Date； null僅可用於欄位等值、$eq、$ne。白名單外之運算子($not $nor $regex $options $exists $where $expr $text等)、 欄位層$and/$or、點路徑、函數值、Symbol鍵、undefined值、空的$nin/$and/$or等一律整批reject， 訊息為invalid find: 原因 at [路徑]，且不連線、不刪除任何數據。
    4. 與select共用同一檢核與同一條件，select(find)命中之數據即本函數刪除之數據； 建議先以select(find)確認命中範圍再刪除。
    5. 條件值若來自可能為undefined、null或空陣列之變數，呼叫端須先自行判斷；undefined值會reject而非被忽略， 空的$nin會reject，$in:[]則為恆假(刪除0筆)。
    6. 語意差異(MongoDB式，依伺服器原生行為，見README)：$ne(比較值非null)與$nin會命中欄位為null或缺欄之數據，$ne:null則僅命中欄位存在且非null者。 需明確表達時可用可攜寫法：排除null為{$and:[{f:{$ne:null}},{f:{$ne:x}}]}，含null為{$or:[{f:null},{f:{$ne:x}}]}。

    註: n為實際刪除筆數，恆等於nDeleted；條件無命中時回傳0亦屬正常結果
